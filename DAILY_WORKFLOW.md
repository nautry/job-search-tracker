# Daily application workflow

The existing GitHub Action collects employer jobs once daily. The existing Google Apps Script sync imports the feed, checks selected unapplied roles, and builds **Daily Dashboard** and **Priority Queue**. Jobs remains the only application-history table. No paid AI API, additional credentials, scheduled service or second scheduled writer is used.

## Your 30–60 minute session

Open Daily Dashboard and spend 30–60 seconds reviewing the three Recommended opportunities and due follow-ups. Decide whether the work, location and actual program interest you. Choose a saved resume: **Mechanical Design** for CAD/mechanisms/assemblies; **Test/R&D** for testing, experiments and instrumentation; **Mechatronics** for electromechanical integration, robotics and sensors. Apply directly on the employer's site. Use Record / defer to update Jobs A:D, then continue with the refill or Priority Queue. The Job search menu can show up to five recommendations. Completion of three applications does not suppress remaining opportunities.

Use ChatGPT for unusual application questions, project framing, genuinely ambiguous requirements and periodic strategy reviews. You should not need another manual job search before applying. No resume tailoring, recruiter contact or application submission happens automatically.

## Decisions and automated investigation

The full available employer description is assessed for degree discipline, actual hardware duties, experience, employment type, location, timing and clearance/export wording. Missing information alone is not a disqualification. A suitable 0–1-year role or explicit early-career role with no contradictory requirements can be Recommended while stating that May 2027 timing is unconfirmed. Generic titles do not prove a graduation cohort. Two required years are Stretch unless the employer explicitly accepts relevant educational/project equivalence. Three or more years, explicit incompatible starts, temporary/intern roles, specialist electrical/software positions, and factory/process/tooling work stay out of the action-ready queue. Current-clearance requirements are Hold when the applicant's possession is unknown. Personal work authorization and program ethics remain the applicant's decision; sector flags never alter scores.

**Recommended** requires strong role/early-career fit and supported application-enabled evidence. **Stretch** identifies a meaningful disadvantage and stays in Priority Queue. **Hold** identifies a material unresolved issue and a concrete next automated check; it is not a default reaction to an absent start date. **Closed / Duplicate / Ineligible** are excluded from active views while preserving all historical records. If no Recommended roles exist, the dashboard explains why and shows up to three plausible candidates with explicit blockers and available check results. Do not treat candidate-only rows as verified recommendations.

Jobs and the feed retain those canonical decisions. Priority Queue displays **Apply** for application-ready Recommended roles, **Stretch** for qualification gaps, and **Needs Review** for Hold or unresolved availability. Today marks dashboard assignments, Backlog marks remaining work. Related aliases/reposts linked to prior submissions, dismissed records or current deferrals stay out of both views. Only one unresolved equivalent posting may occupy the queue; distinct legitimate requisitions remain separate.

The collector performs up to 40 public ATS/form checks per run and rotates priority away from already fresh positives. Application statuses remain private in the Sheet. The same authorized Sheet sync performs at most eight additional read-only checks targeted at high-ranking unapplied records; simple onEdit refreshes never make authorization-requiring network requests. Greenhouse job-specific application fields and Workday canApply states provide stronger evidence than HTTP 200. Other providers require a usable public application form where observable. Accessible listings without such evidence remain inconclusive. The public system cannot verify active interviewing, internal hiring urgency or eventual submission acceptance.

Checks are refreshed daily or on demand. Supported positive evidence can remain usable for 72 hours while being rechecked after 24 hours; failed checks expose a reason rather than silently confirming activity. A missing job from failed, partial or keyword-scoped collection never establishes closure. Complete-board absence remains uncertain; explicit employer closure, disabled applications, expired deadlines or official detail 404/410 can establish closure. Public-page/ATS conflicts stay inconclusive. There are no access-control bypasses or retries on 403/429.

## Identity, dates and history

Exact provider/requisition evidence consolidates repeat observations, tracking URL variants and multi-location records. Different provider namespaces are not equated by coincidental numeric IDs. Strong title/location/description similarity links possible reposts without merging distinct requisitions. Related application history remains visible; suspected equivalent reposts are not silently recommended again. First-seen dates and stable job IDs are preserved.

Employer publication date is independent of first seen, update time and verification time. Unknown employer dates remain Unknown. Recent roles receive higher recency weight; older open roles remain in Jobs outside the active application views. Store the actual application date in Jobs B. Daily reporting explicitly uses **America/Indianapolis**, including midnight boundaries. Application dates are never inferred from sync times. Statuses, dates, notes and optional AI deferrals are preserved during sync. A date correction requires explicit user authorization and applies only to the named records.

Active Dashboard and Priority Queue now require an original employer publication date within **45 calendar days**, measured using the tracker's Indianapolis calendar. The window rolls daily, excludes unknown/future dates, and does not reset for first-seen, update or verification timestamps. An older open position remains in Jobs and retains all application/follow-up history; it does not qualify for the active application views. The collector avoids routine verification requests on age-ineligible roles. Fit scoring, employer mix and role exclusions are unchanged.

Exact duplicate groups retain one canonical representative and all linked historical records. Current ATS posting/internal identifiers establish exact identity; an old alias list without corroborating identifiers is only a suspected relationship. Similar titles and shared human-readable HR codes do not justify automatic merging. Redundant unannotated Not Applied aliases are hidden in Jobs; applied, noted or deferred records stay visible. No historical application record is deleted, and a newly annotated alias is restored by the updated script.

## Practical controls and installation

Use **Job search → Refresh dashboard / refill** to rebuild views and perform limited supported checks without rerunning the collector. Updating Jobs A:D or AI triggers a views-only refill. **Refresh jobs** imports the existing feed. Trigger GitHub Run workflow only after a missed/failed collection. Sources shows partial coverage and failures, including RTX; source archives stay hidden and are not recreated on every refresh. No archive/application records are deleted.

To install this iteration, open the existing Sheet → Extensions → Apps Script. Replace Code.gs with the current repository version, save, and run **syncJobs** once. Reuse the existing syncJobs trigger; do not add another one. Reopen the Sheet for the menu. Confirm Settings!B5 reports success and B25 includes **2026-11-25-recency-dedup-v5** (or a newer version). A GitHub commit alone does not deploy the bound script. Settings records the actual script version only after successful sync; any connector-generated preview is explicitly labeled pending until installation is verified. The existing v4 script honors the new feed's queue-eligibility gates, while v5 adds calendar-boundary checks and reversible alias-row collapsing within the Sheet. Native Jobs table dropdowns and typed date columns are preserved without reapplying incompatible range formatting.

If contextual AI interpretation would help with a material ambiguity, an optional Work-mode session can inspect the at-most-three candidate-only rows and public descriptions, record supported findings and suggest a targeted next step. This is on-demand assistance, not AI running in the daily schedule. Preserve the RTX offer and follow-up until the applicant intentionally changes them.
