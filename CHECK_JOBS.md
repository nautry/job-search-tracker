# Daily job check

1. Open **Daily Dashboard**. The existing GitHub workflow discovers and ranks jobs daily; the existing Google sync updates the views. Do not rerun collection for a normal session.
2. Spend **30–60 seconds** checking the three Recommended roles, publication dates, concise fit reasons and caveats. Decide whether the work, program and location interest you. Missing start dates are caveats when the full description otherwise supports entry-level fit. Recommended never means guaranteed qualification or active interviewing.
3. Choose a saved **Mechanical Design**, **Test/R&D**, or **Mechatronics** resume. The system suggests a variant; it does not generate a tailored resume automatically.
4. Open the linked employer application and submit yourself. Use **Record / defer** to reach the correct Jobs record. Set **A: Status** to Applied and **B: Applied date** to your actual local submission date. Optionally update C: Follow-up and D: Notes. Do not substitute the date you discovered the job or refreshed the Sheet.
5. The dashboard removes submitted roles and refills. A completed daily target never blocks further recommendations. To see up to five at once, use **Job search → Show up to five recommendations**; otherwise use Priority Queue.
6. Check due follow-ups, especially the existing RTX verbal offer's written-offer and decision-deadline confirmation. No recruiter is contacted automatically.

Use optional **Jobs AI: Deferred until** to postpone a role; it returns after that date. Use Not Interested to dismiss it permanently. Statuses remain Not Applied, Applied, Interviewing, Offer, Rejected, Not Interested, Withdrawn.

Spend approximately **30–60 minutes**, normally submitting 1–3 worthwhile applications. Use ChatGPT for unusual short-answer questions, applications that need project framing, genuinely ambiguous requirements and occasional strategy review. Routine discovery and screening run automatically. If no recommendations qualify, the dashboard explains the dominant blocker and shows at most three candidates undergoing targeted checks; this is not an instruction to research the entire database.

**Recommended** = relevant duties, realistic early-career expectations, supported public application-enabled evidence and no explicit incompatible requirement. **Stretch** = meaningful disadvantage such as two required professional years without explicit project equivalence. **Hold** = a material unresolved issue, with automatic rechecking where supported. Closed, Duplicate and Ineligible remain in Jobs but outside the active queue.

Priority Queue uses **Apply** for a currently application-ready Recommended record and **Needs Review** for Hold or unresolved verification; **Stretch** stays separate. Today rows are already assigned to the dashboard; Backlog rows are additional work. Related reposts linked to submitted, dismissed or deferred records are withheld, and suspected equivalent listings occupy at most one queue slot. All original records remain in Jobs.

Active views use a **rolling 45-calendar-day employer posting window**. Unknown or future posting dates are withheld; first seen and source refresh never substitute for publication. Older Jobs records and application follow-ups remain available. Confirmed exact aliases have one representative; redundant, unannotated Not Applied rows are collapsed, never deleted. Similar titles with different ATS identities remain separate or explicitly suspected.

The feed enforces the age cutoff for the existing bound script. Install repository Code.gs and run syncJobs once to add immediate local cutoff checks and automatic alias-row collapsing. Settings!B25 then reports **2026-11-25-recency-dedup-v5**. A pending preview does not prove deployment. Reuse the existing daily trigger. Role-fit weights and exclusions have not changed in this iteration.

Product-use flags have zero ranking adjustment. You decide whether the actual program is acceptable. The soft 70–75% defense/dual-use preference never pads the queue.
